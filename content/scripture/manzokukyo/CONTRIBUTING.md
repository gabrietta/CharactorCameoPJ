# 参加ガイド

満足教の教典づくりへの参加方法です。一節の思いつきから、章まるごとの執筆、誤字や文語の添削まで歓迎します。

## 参加のしかた

| やりたいこと | 方法 |
|---|---|
| 一節・アイデアだけ出したい | GitHubのIssue「教典の提案」を立てる。または [fragments.md](fragments.md) へ追記するPRを出す |
| 章を書きたい | [outline.md](outline.md) で「募集中」の章を選び、Issueで名乗り出てから `text/` にファイルを作ってPRを出す |
| 既存の章を直したい | 該当ファイルを直してPRを出す。大きく書き換える場合は先にIssueで相談する |
| 文語の誤り・誤字を直したい | そのままPRを出してよい |

PRを出す前に、次を実行して形式を確認してください。

```bash
node scripts/check-scripture.mjs
```

## 書き方の約束

詳しくは [style-guide.md](style-guide.md)。要点だけ:

- **本文は文語訳聖書調**（〜なり、〜せよ、〜なかれ、見よ）。
- **教祖の言葉だけは、ですわ調の口語**。一人称は公的な場で「わたくし」、私的な場で「あたし」。
- **付記・規程は、淡々とした内部文書調**。怖さの主力はここ。
- **配分は、怖さ7割・コメディ2割・意味深1割**。一節ごとではなく、章全体でこの配分になるようにする。怖い節と可笑しい節を分けずに混ぜる。
- 怖さは、はっきり描かない。規程の行間、答えない教祖、黒塗り、数の合わない名簿で出す。

## 守ること

1. **現実の宗教・宗派・聖人・実在の人物を名指ししない。** 聖典という形式のパロディはよいが、特定の信仰をからかわない。
2. **自傷・自死・摂食制限を勧めたり美化したりしない。** 「完了者」がどうなったかは、死亡や消失と断定しない。
3. **勧誘・献金の呼びかけに読める文を書かない。**
4. **キャラクター公式設定と矛盾させない。** 公式設定は `content/characters/zannenin/character.json`。[source-index.md](source-index.md) に要点がある。
5. **未定義のものは勝手に確定させない。** 例: ALPHACLAVEで確定している信者は B（ツッコミ信者）、F（風花、悪ノリ信者）、Z（教祖が兼任）だけ。他の英字の信者を登場させるときは、章末の編纂注に「新規案」と書く。
6. **謎を解かない。** [mysteries.md](mysteries.md) に載っている謎は、編纂責任者の判断なしに答えを書かない。ほのめかしや新しい手がかりは歓迎。新しい謎を作ったら登録する。
7. **作中用語は用語集に合わせる。** 新しい用語を作ったら、同じPRで [lexicon.md](lexicon.md) に追加する。
8. **登場する人物は女性にする。** シリーズの配役方針に合わせる。名もない信者は「信女」と書く。

## 章ファイルの形式

```markdown
---
id: hunger              # 英小文字とハイフン。章の固定ID
part: 1                 # 部の番号
chapter: 1              # 通し章番号（draftの間は変わりうる）
title: はじめに空腹ありき
summary: 空腹のはじめ。…  # 章の頭に置く一行の梗概（文語）
status: draft           # draft / review / adopted
---

# はじめに空腹ありき

**1**　はじめに空腹ありき。

**2**　空腹は闇の上をただよい、……

> 【付記】 ……

## 編纂注

- 公式設定に基づく要素、新規案の範囲、相談したい点など
```

- `part` は 0＝前付（序、満足連祷）、1〜3＝各部、9＝付録（満足暦、奥付）。
- `chapter` は本文の通し章番号。前付と付録は番号を持たないので `0` にする。ファイル名の先頭の数字が並び順になる（前付 `00-1-` `00-2-`、本文 `01-`〜、付録 `90-`〜）。
- 節は `**番号**`＋全角空白＋本文。1節は1行。節の間は空行。
- 付記・規程は `> 【付記】` `> 【規程】` で始まる引用ブロックにする。節番号は付けない。
- `## 編纂注` は制作用のメモ。書籍・Wikiに載せるときは外す。
- 別の章の節とつながる節を書いたら、[cross-references.json](cross-references.json) に引照を足す（例: `"hunger:6": ["litany:8"]`）。書き出した本では、章末に「引照」として表示される。存在しない節を指すと検査で止まる。

## 採否の流れ

1. **draft**: 誰でも書き足し・書き換えできる。
2. **review**: 編纂責任者が確認中。大きな書き換えはIssueで相談してから。
3. **adopted**: 教典として採用。以後、**章番号と節番号は固定**する。
   - 節を削るときは消さずに `**7**　（欠番）` と残す。欠番の理由は編纂注に書く。
   - 節を足すときは章の末尾に足す。
   - 語句の誤りの修正はPRでできる。意味が変わる修正は編纂責任者の判断。

採用されなかった節は、消さずに `rejected.md` へ移して理由を残します（別の場面で再利用できる素材になります）。

## AIを使って書く方へ

AIで下書きを作ってもかまいません。その場合もこのガイドと文体ガイドを読ませたうえで、人が読んで直してからPRにしてください。公式設定にない事実をAIが補っていないか、特に確認してください。
